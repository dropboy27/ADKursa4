# Codebook: разметка объектов на игровых кадрах Valorant

**Проект:** Сравнительный анализ влияния ручного и искусственного обогащения данных на качество и устойчивость обучения моделей машинного обучения.

**Исходный датасет:** [keremberke/valorant-object-detection](https://huggingface.co/datasets/keremberke/valorant-object-detection).

## 1. Цель разметки

Целью является обнаружение противников, союзников, лежащего и установленного spike на игровых кадрах Valorant.

Разметка выполняется в соответствии с классами исходного датасета для последующего обучения моделей детекции объектов и ручного обогащения данных.

## 2. Единица разметки

Единицей разметки является отдельный игровой кадр.

Кадры извлекаются из собственной записи игры с частотой 1 кадр в секунду. После ручного отбора изображения растягиваются до размера **416 × 416 пикселей** без сохранения исходного соотношения сторон.

Каждый целевой объект получает отдельную прямоугольную рамку и одну метку класса. На изображении допускается несколько объектов одного или разных классов.

Изображения без целевых объектов сохраняются с пустой разметкой.

## 3. Описание классов

| ID | Класс | Условия присвоения |
|---|---|---|
| 0 | `dropped spike` | Spike лежит на поверхности. Под ним может присутствовать оранжевый контур. Рамка охватывает только сам предмет. |
| 1 | `enemy` | Противник, выделенный красным контуром. Размечается только видимая часть тела без расширения рамки на оружие. |
| 2 | `planted spike` | Spike установлен: стоит на поверхности и мигает синим. Рамка охватывает только сам предмет без окружающих эффектов. |
| 3 | `teammate` | Союзный персонаж без красного контура противника. Размечается целиком по отображаемому силуэту, в том числе просвечивающему сквозь стены. |

Названия классов и числовые ID сохраняются при экспорте разметки.

## 4. Общие правила разметки

**Правило 1.** На изображении размечаются все целевые объекты, соответствующие настоящему Codebook. Каждый экземпляр получает отдельную рамку.

**Правило 2.** Рамка должна плотно охватывать объект или его размечаемую часть. Лишний фон по возможности исключается. Координаты рамки не должны выходить за границы изображения.

**Правило 3.** Для противников размечается только видимая часть тела. Если из-за препятствия видна только голова, рука или другая часть тела, рамка охватывает эту часть. Скрытые части не достраиваются.

**Правило 4.** Для союзников рамка охватывает полный отображаемый силуэт, включая части, просвечивающие сквозь стену. Если персонаж выходит за границу кадра, рамка ограничивается изображением.

**Правило 5.** Оружие не учитывается при определении границ персонажа. Выступающее оружие не должно расширять рамку тела или силуэта.

**Правило 6.** Для spike размечается только сам предмет. Оранжевый контур, синее свечение, тени и окружающие эффекты не используются для расширения рамки.

**Правило 7.** Spike, который несёт персонаж, а также spike во время установки или обезвреживания не размечается. Персонаж при этом размечается по правилам соответствующего класса.

**Правило 8.** Маленькие объекты и случаи с неоднозначным классом или границами отмечаются для последующего обсуждения. До завершения независимого этапа аннотаторы не сверяют решения друг с другом.

**Правило 9.** Не размечаются собственные руки и оружие игрока от первого лица, миникарта, значки интерфейса, портреты персонажей, трупы, тени и эффекты способностей. Отображаемый сквозь стену силуэт союзника размечается согласно правилу 4.

**Правило 10.** Не допускается угадывать наличие объекта, его класс или скрытые границы. При недостатке визуальных признаков случай выносится на обсуждение.

## 5. Примеры разметки

| Ситуация | Разметка | Причина |
|---|---|---|
| Противник с красным контуром полностью виден | Рамка `enemy` по границам тела | Объект уверенно определяется как противник |
| Из-за укрытия видна голова противника | Рамка `enemy` вокруг головы | Размечается только видимая часть |
| Силуэт союзника просвечивает сквозь стену | Рамка `teammate` вокруг полного отображаемого силуэта | Для союзников учитывается силуэт через препятствие |
| Spike лежит на поверхности над оранжевым контуром | Рамка `dropped spike` вокруг предмета | Оранжевый контур не входит в границы объекта |
| Spike стоит и мигает синим | Рамка `planted spike` вокруг предмета | Объект находится в установленном состоянии |
| Персонаж несёт, устанавливает или обезвреживает spike | Spike не размечается | Эти состояния исключены из разметки |
| Небольшой объект трудно уверенно распознать | Комментарий для последующего обсуждения | Класс объекта не должен определяться угадыванием |
| На изображении отсутствуют целевые объекты | Пустая разметка | Кадр является отрицательным примером |

Примеры используются для единого понимания правил аннотаторами.

## 6. Процедура разметки

Разметка выполняется в **CVAT** по единому Codebook.

Каждое изображение размечается двумя аннотаторами отдельно, независимо и с нуля. До завершения независимой разметки участники не просматривают результаты друг друга и не обсуждают решения по конкретным кадрам.

Для каждого изображения фиксируются:

- Имя файла или идентификатор изображения.
- Идентификатор аннотатора.
- Классы объектов.
- Координаты рамок.
- Комментарий при наличии спорного случая.

После завершения независимого этапа первоначальные варианты сохраняются для сравнения. Согласованные исправления вносятся в отдельную итоговую разметку.

## 7. Разрешение разногласий

После завершения независимой разметки результаты сопоставляются по именам изображений.

Проверяются различия в наличии объектов, их классах, количестве и границах рамок.

Для оценки согласованности используются:

- **Percentage Agreement** отдельно по каждому классу — доля кадров, на которых совпадает решение о наличии или отсутствии класса.
- **Cohen’s Kappa** отдельно по каждому классу — согласованность тех же бинарных решений с учётом случайного совпадения.
- **IoU** — отношение площади пересечения двух рамок к площади их объединения для оценки совпадения границ.

Процент согласия и каппа по наличию классов не заменяют проверку геометрии рамок.

Спорные случаи, включая маленькие объекты, обсуждаются с опорой на изображение и Codebook. Для каждого случая согласуются наличие объекта, его класс и границы.

Первоначальные независимые варианты сохраняются. Метрики согласованности рассчитываются до внесения согласованных исправлений.

## 8. Контроль качества

Перед началом разметки проверяются размер изображений, список классов и соответствие числовых ID.

При проверке разметки контролируются:

- Полнота разметки целевых объектов.
- Отсутствие повторных рамок одного экземпляра.
- Правильность классов и их ID.
- Плотность рамок и нахождение координат внутри изображения.
- Соблюдение правил для видимой части противника и полного отображаемого силуэта союзника.
- Исключение оружия и окружающих эффектов из определения границ объектов.
- Отсутствие разметки исключённых элементов и состояний spike.
- Сохранение кадров без целевых объектов с пустой разметкой.
- Рассмотрение комментариев по маленьким и неоднозначным объектам.

При необходимости правила уточняются в согласованной версии Codebook. Уточнения применяются ко всем изображениям, которых они касаются.
